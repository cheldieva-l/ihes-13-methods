- `fast-20`: `puzzle_id 983..1002`.

- Checkpoint-кривая: не реже одного раза в 2 000 эпох; ранние точки 250/500/1000

- Сильное подтверждение улучшения: все пути валидны и верхняя граница 95% CI для
  `candidate_length - incumbent_length` ниже нуля.

## Особенность IHES, которую нельзя потерять

Обычный 3x3 solver решает только фактор по углам и рёбрам. В IHES дополнительно важны
изображения центров: 24 center-picture позиции кодируют шесть центров, каждый из которых
имеет четыре ориентации. Средние слои `f1`, `r1`, `d1` входят в официальные генераторы.

Поэтому обычный 3x3-путь считается только префиксом. Итог принимается исключительно
после replay всех 72 позиций. Для ветки универсального solver требуется отдельная
center-coordinate/PDB и выбор такого подъёма 3x3-решения, который минимизирует
`длина префикса + точная цена исправления центров`.

## T1 — что переносится из `TRANSFORMER_AZ_RECIPE.md`

- один token на физическую деталь: для IHES ожидаются 26 деталей + CLS;
- общий Transformer trunk, Q-head на 18 действий и scalar V-head;
- sparse-Q на серединах non-backtracking random walks;
- точные BFS/PDB anchors;
- symmetry-expanded обучение только после проверки action transport;
- Q/V consistency, blend с MLP, reverse frame и exact endgame splice;
- replay каждого найденного пути.

Не переносятся как готовая истина: веса tetraminx/555, 24-action head, исходные BFS
глубины, вывод о насыщении после 1500 эпох, число frames и исходные blend-веса.

## Ближайшая последовательность действий

1. Получить лучший доступный submission через Kaggle API и сохранить его hash.
2. Запустить на Molab `E001`: `puzzle_id=9`, короткий beam, затем полный 72-position replay.
3. Подключить проверенные symmetry/reverse transforms из IHES-ноутбука Андрея.
4. Запустить `E002–E004` на неизменном `fast-20`.
5. Параллельно вывести IHES 26-piece layout и T1 input encoding из официальных generators.
6. После первого T1 checkpoint сравнить его с T0 по этому же протоколу.
7. Только победителей переносить на `selection-50`, затем на дорогие beams.

## Вычислительные ресурсы и задачи пользователю

- Для первого этапа достаточно **двух Molab-аккаунтов** с одной 12-часовой GPU-сессией
  в каждом: один поток для T0/inference, второй для T1 training.
- Если каждый аккаунт действительно разрешает две одновременные GPU-сессии, двух
  аккаунтов достаточно и для четырёх потоков. Третий аккаунт пока не нужен.
- Требуется открыть в браузере вторую уже авторизованную Molab-сессию, когда E001
  подтвердит корректную загрузку модели и replay. Пароли и коды входа в журнал и
  ноутбуки не записываются.

## Правила безопасности результата

- Невалидный путь сохраняется в отчёте как `valid=False`, но никогда не заменяет incumbent.
- Ошибка одного кубика не останавливает независимые кубики.
- Нет `assert`/fixed-canary исключений, останавливающих удалённый запуск.
- Submission создаётся как покубиковый минимум только среди replay-valid путей.
- Перед отправкой: два независимых полных replay всех 1003 строк и проверка суммы длин.
