## 2. Математическое определение

Состояние обычного кубика — вектор-перестановка `s` длины 54. Цель `e = [0,1,...,53]`. Применение генератора `g` фиксируем явно: `next_state[j] = state[g[j]]`, то есть pullback / `state[g]`. В документации привести хотя бы один числовой проверенный пример.

Набор имён: `f0,-f0,f1,-f1,f2,-f2,r0,-r0,r1,-r1,r2,-r2,d0,-d0,d1,-d1,d2,-d2`. Сам словарь перестановок, а не неформальное название оси, является точным контрактом соревнования.

IHES: 48 нецентральных позиций + 6 блоков по 4 позиции ориентированных центров. Нужно свернуть каждый блок центра в одну обычную центральную метку и получить 54 класса. Нельзя просто отрезать последние 18 чисел.

Пусть `q` отображает 72 позиции/метки в 54 класса; `r_j` — представитель класса j. Тогда `project(s)[j] = q(s[r_j])`. Для каждого IHES-генератора проверить, что все представители каждого класса дают один результат и что

`project(apply72(s,g72)) == apply54(project(s),g54)`.

Сначала построить quotient, затем найти и сохранить переименование классов в нумерацию p001. Важно: перестановка меток/позиций должна согласовываться одновременно для всех 18 генераторов; для обратных имён проверить композицию с положительным ходом. При несовпадении не «лечить» заменой цели или произвольным инвертированием всех слов.

Исходник `ihes13/projection333.py` — полезный черновой геометрический адаптер, а не уже доказанное соответствие статье. Его порядок граней URFDLB нельзя объявлять p001 без сравнения.

## 3. Генерация

Для официального решающего слова `w = a1.a2....aL`:

`inverse_word(w) = inverse(aL)....inverse(a2).inverse(a1)`.

Пустое слово обращается в пустое. `initial_state_333 = apply54(e, inverse_word(w))`. Затем проверить:

1. `apply54(initial_state_333, w) == e` — корректность baseline.
2. `initial_state_333 == project(official_initial_state_ihes)` — независимая связь с настоящим IHES-входом.
3. Вся строка — перестановка 0…53, ID уникален и сохранён.

Не менять исходное слово только ради уменьшения sample-score. Требуется совместимый базовый сабмит, а не оптимальный решатель. Дополнительно можно выдать оптимизированный baseline с пустыми решениями для всех фактически собранных входов, но оставить исходный sample отдельно и подписать оба score.

Первая контрольная выборка: все обнаруженные собранные состояния, одноходовое состояние, ID 9 и 999; затем обязательно все строки. Не привязывать разрешение дальнейших независимых проверок к фиксированному числу успешных canary.

## 4. CSV и пустые значения

| Файл | Колонки | Значения |
|---|---|---|
| test.csv | initial_state_id, initial_state | Целый ID; quoted-строка 54 целых через запятую |
| sample_submission.csv | initial_state_id, path | Тот же набор ID; генераторы через точку |
| generation_paths.csv | initial_state_id, scramble_path | Обратное слово через точку |

Пустой путь сериализуется как пустое CSV-поле: строка `0,` либо `0,""`. Оба случая одинаковы. Это не `UNSOLVED`, не `0`, не `None` и не строка `nan`. Пустой путь валиден **только если состояние уже равно e**, и имеет длину 0.

Разрешить пустое значение, полученное CSV-парсером, как пустой путь, но не неизвестный токен. Не использовать `str(value)` для NaN. Не удалять молча пустые токены внутри непустого слова: `f0..r0` — ошибка формата. Допустимость внешних пробелов определить явно и одинаково в validator и metric; предпочтение: удалить только внешние пробелы, затем строгий whitelist токенов.

Неверные/дублированные/пропущенные/лишние ID — ошибка сабмита. Порядок строк можно принимать любой с проверенным объединением по ID; публичный образец сохраняет исходный порядок.

## 5. Метрика

`score(solution: pd.DataFrame, submission: pd.DataFrame, row_id_column_name: str) -> float`.

Результат = **сумма количества генераторов** по всем оцениваемым строкам, меньше лучше. Путь с неизвестным ходом или неверным конечным состоянием делает сабмит невалидным, а не получает короткую длину. В пользовательском отчёте сохранять F и причину; не включать невалидные решения в min-merge.

Самодостаточность: никакой сети во время scoring, никакой загрузки GitHub/Kaggle API. Зафиксированные 18 перестановок встроены в metric-артефакт или гарантированно доступны штатным способом metric; hash сверяется при сборке. Grader не должен доверять загруженному участником puzzle_info.

Предпочтительный private solution: `initial_state_id,path,Usage`, где path — доверенное reference-слово IHES. Grader восстанавливает вход из обратного reference-слова на обычном кубике и проверяет submission-путь. Это позволяет не зависеть от внешнего test.csv. До фиксации схемы проверить, какие колонки Kaggle передаёт Python-метрике и как обрабатывается Usage. При необходимости выбрать схему с доверенной строкой initial_state, но задокументировать её.

Полный public score: сначала испытать `Usage=Public` для всех исходных строк. Проверить требования Kaggle к private leaderboard и финальному ранжированию: публичный и итоговый score должны соответствовать заявленной полной сумме, а не случайной доле строк. Если платформе требуется другой split, остановить только публикацию и решить явно; не менять метрику молча.

Ограничения платформы по прочитанной документации: metric выполняется без интернета, до 30 минут, нужны аннотации типов. Ошибки участника — `ParticipantVisibleError` с краткой причиной/ID. Это необходимое отбраковывание неверного сабмита, а НЕ запрещённый assert, обрывающий сбор других ноутбуков.

## 7. Обязательные проверки

- Все 18 массивов — перестановки 0…53; все g·inverse(g)=e; каждый четверть-поворот имеет порядок 4.
- Все 18 ходов и репрезентативные составные слова согласованы с quotient IHES и p001.
- Для всех входов: обратное слово создаёт нужный вход, исходное слово возвращает в e; второй независимый replay даёт тот же результат.
- Номер и размер исходной таблицы получены из файла, а не зашиты как условие остановки.
- Собранное состояние + пустой путь принимается, score 0; несобранное + пустой отклоняется.
- CSV `id,` и `id,""` одинаково проходят настоящий sandbox; слово `nan`, двойная точка и неизвестный ход отклоняются.
- Повтор ID, пропущенный ID, лишний ID и переставленный ID не обходят проверку.
- Добавление `f0.-f0` к валидному слову сохраняет корректность и увеличивает score ровно на 2.
- Удалённый ход/неверное направление на специально проверенном примере дают invalid; не считать произвольное удаление обязательно неправильным без replay.
- Один и тот же комплект источников и кода даёт одинаковые hashes артефактов; timestamp отделён от детерминированных данных.
- Sandbox-score исходного baseline совпадает с независимо вычисленной суммой, а не только с «Success».
- Public data не содержит credentials, private solution или служебных локальных путей.

Все результаты сохраняются. Неудачная проверка не мешает выполнить независимые проверки и получить диагностический отчёт. Но соревнование с дефектом генераторов, метрики или данных не запускать публично.
