## Правила загрузки ресурсов

- GPU всегда получает заранее подготовленную очередь минимум из двух экспериментов.
- В ожидании GPU Codex делает анализ, validator, U2 coordinate или готовит следующий run.
- WIP одновременно: максимум 1 inference, 1 training, 1 CPU/engineering item.
- Маленький beam/fast-20 обязателен до дорогого запуска.
- После каждого запуска фиксировать git SHA, профиль/URL, wall/GPU time, valid и delta.
- Не продолжать ветку только из-за уже потраченного времени; решает будущая отдача.
- С 21 сентября действует freeze: только лучшие методы, merge, replay и submission.

## Основание управления

- Critical path определяет минимальный срок и задачи без запаса времени:
  https://www.pmi.org/-/media/pmi/documents/public/pdf/pmief/skills-for-life-english.pdf
- Resource leveling нужен, когда несколько веток конкурируют за один GPU:
  https://www.pmi.org/learning/library/scheduling-resource-leveling-project-progression-8006
- WIP limits уменьшают многозадачность и выявляют bottleneck:
  https://www.atlassian.com/agile/kanban/wip-limits/
